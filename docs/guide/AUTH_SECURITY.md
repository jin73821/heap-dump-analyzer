## Authentication & Security

Spring Security **7.1** 세션. `/login` 공개, `/admin/**` + `/api/admin/**` ADMIN 전용. **CSRF 보호 유지 (면제하지 않음)**: `/api/admin/**`, `/api/settings/**`, `/api/llm/{enabled,config,apikey,test-connection,chat-prompt,chat-restore-mode,file-attach,ratelimit}`, `/api/servers/{scan-interval,ssh-local-user}` — 모두 `authorizeHttpRequests(auth -> auth.requestMatchers(...).hasRole("ADMIN"))` 매처와 1:1 미러링. 그 외 `/api/**` 는 CSRF 면제 (인증은 유지). **새 ADMIN mutation 추가 시 SecurityConfig 두 곳 (authorize + csrf ignore) 동시 갱신 필수**. `SecurityConfig` 는 lambda DSL + `@EnableMethodSecurity` (`@PreAuthorize` 지원) 사용 — `.and()` chain / `@EnableGlobalMethodSecurity` / `antMatchers` 미사용.

**Spring Session JDBC**: `SPRING_SESSION` / `SPRING_SESSION_ATTRIBUTES` 자동 생성. 무동작 만료 60분, cleanup cron 10분. 앱 재시작에도 로그인 유지.

**DB 장애(WAS 정상·DB 비정상) 표시 규약 (2026-09-26, `docs/DB_OUTAGE_DISPLAY_PLAN.md`):** 세션 저장소가 DB 라 장애 시 쿠키 있는 모든 요청이 **컨트롤러 전 세션 필터에서 죽고** Tomcat 이 `/error` 로 ERROR 디스패치한다. ERROR 디스패치는 세션 필터를 타지 않아(`spring.session.servlet.filter-dispatcher-types=request,async`) 익명이므로 `SecurityConfig` 가 **`dispatcherTypeMatchers(DispatcherType.ERROR).permitAll()` + `/error` permitAll + CSRF `DispatcherTypeRequestMatcher(ERROR)` 면제**를 둔다 — 이게 없으면 503 대신 로그인 리다이렉트/401 `SESSION_EXPIRED` 가 나가 **DB 장애가 세션 만료로 오인**된다(종전 실제 동작). 로그인 실패 핸들러는 `InternalAuthenticationServiceException`(사용자 조회 실패) → `/login?error=unavailable` → `unavailableMessage`(자격 증명 오류 문구와 분리, `AuthEventListener` 도 실패 횟수에 넣지 않는다). Hikari `connection-timeout=5000`·`validation-timeout=2000`(기본 30초 대기 방지 — 앱·k8s properties 양쪽). ⚠ **`DataSourceConfig` 가 직접 만드는 빈에는 `spring.datasource.hikari.*` 가 저절로 바인딩되지 않는다** — Boot 자동설정처럼 `@ConfigurationProperties("spring.datasource.hikari")` + `HikariDataSource` 반환형이어야 한다(첫 실검증에서 요청당 30초·로그인 60초로 드러남, `DbOutageDisplaySmokeTest` 가 고정). ⚠ **`application.properties` 는 `.gitignore` 대상**(`*.properties`)이라 새 환경엔 키가 없을 수 있다 — 그래서 5초·2초는 `DataSourceConfig.DEFAULT_*` **코드 기본값**이고 properties 키는 덮어쓰기용이다(`ui.refresh.interval-sec` 도 키가 없으면 `@Value` 기본 60 + settings.json 영속만 되고 properties 왕복은 안 된다 — 새 환경은 키를 수동 추가). 실측(REJECT/DROP 모두): 요청당 약 6초, 복구 즉시. ⚠ 장애 중엔 **로그인도 불가**하다(로그인 GET 이 CSRF 토큰을 세션에 쓰고, POST 가 세션의 토큰을 읽는다) — 새 브라우저도 503 페이지를 본다. 실검증은 `iptables … --dport 3306 -j REJECT/DROP` 으로(CHANGELOG 2026-09-26). 회귀 방어 `DbOutageDetectorTest`(3)·`DbHealthServiceTest`(2)·`DbAwareErrorControllerTest`(4)·`DbOutageDisplaySmokeTest`(3).

## 함정

1. **`InteractiveAuthenticationSuccessEvent` 사용 필수** — `AuthenticationSuccessEvent`는 `ProviderManager`에서 발행되는데 그 시점은 **세션 고정 보호 적용 전**이라 `request.getSession().getId()`가 곧 폐기될 옛 세션 ID. SPRING_SESSION의 ID와 매칭 안 됨. `InteractiveAuthenticationSuccessEvent`는 `AbstractAuthenticationProcessingFilter#successfulAuthentication()`에서 sessionStrategy 적용 *후* 발행. 로그인 이력의 session_id를 활성 세션 매칭에 쓰는 코드는 모두 이 이벤트 사용.

2. **활성 세션 본인 종료 거부 (서버 측)** — `DELETE /api/admin/active-sessions/{id}`는 `request.getSession(false).getId()`와 path variable 비교 → 일치 시 400 + 한글 메시지. 클라이언트 `isCurrent` 플래그는 UI 힌트일 뿐, 실제 거부는 백엔드. 종료는 `FindByIndexNameSessionRepository.deleteById()` 우선 (속성 테이블 정합성), 폴백은 `SPRING_SESSION_ATTRIBUTES` → `SPRING_SESSION` 직접 DELETE. **다중 선택 종료(2026-11-03)** `POST /api/admin/active-sessions/terminate` `{sessionIds:[…]}`(1회 500개)도 같은 `terminateOne` 을 지나며 본인 세션은 요청에 들어와도 건너뛴다(`skippedSelf`). 응답은 `terminated/alreadyGone/skippedSelf/failed` 건수, `success` 는 실패 0건일 때만 true — 한 건 실패로 멈추지 않는다. 감사 로그 `[Session] action=terminate target={소유자} by={who}`·`action=bulk-terminate …` 에 세션 ID 는 쓰지 않는다(세션 ID 자체가 자격이다). 회귀 방어 `AdminActiveSessionsTerminateTest`.

3. **로그인 페이지 새로고침 메시지 잔존** — Spring Security가 `/login?error=true`로 리다이렉트 → F5 시 같은 메시지 재표시. `login.html` 최상단 인라인 스크립트가 `?error`/`?logout` 발견 시 즉시 `history.replaceState({}, document.title, location.pathname)`.

15. **Spring Session JDBC 3.x ↔ 2.x 직렬화 비호환** — Spring Session 3.x (Boot 3) 는 2.x (Boot 2.7) 가 저장한 SPRING_SESSION_ATTRIBUTES 행을 deserialize 못 함 (`ConversionFailedException: byte[] → Object`). 응답 자체는 200 이지만 백그라운드 session save 가 실패해 로그 오염. **Boot 버전 다운/업그레이드 시 `TRUNCATE SPRING_SESSION_ATTRIBUTES; TRUNCATE SPRING_SESSION;` 필수** — 모든 사용자 재로그인 발생.

21. **`DisabledException`을 `loadUserByUsername()`에서 직접 throw 금지** — `DaoAuthenticationProvider.retrieveUser()`가 `UserDetailsService`의 모든 예외를 `catch (Exception ex)`로 잡아 `InternalAuthenticationServiceException`으로 wrapping함. 결과적으로 `SecurityConfig`의 failureHandler에서 `ex instanceof DisabledException`이 절대 true가 되지 않아 `/login?error=disabled` 로 분기되지 않음. **올바른 방법**: `enabled=false`인 `UserDetails`를 반환 → Spring Security의 `DefaultPreAuthenticationChecks.check()`가 `retrieveUser()` 반환 후 `DisabledException`을 throw (wrapping되지 않음).

27. **AJAX 가 인증 리다이렉트를 "성공"으로 오인** — `fetch` 는 302 를 자동 추종하므로 미인증 API 호출이 `/login` HTML 을 **200** 으로 받는다. `r.ok` 만 보는 코드(`Common.fetchJSON` 포함)는 이를 성공 처리하고, 응답 객체의 필드는 전부 `undefined` 가 된다 → 저장이 안 됐는데 "저장됨" 이 뜨는 조용한 실패. 2026-08-06 에 `/api/**` 를 401 JSON 으로 바꿔 서버 측에서 차단했다(위 *세션 만료 응답 규약*). **응답 본문을 신뢰하기 전에 `success === true` 를 확인**하는 습관을 유지할 것 — `memo.js` 의 `assertSaved()` 가 2중 방어 레퍼런스. 또한 `defaultAuthenticationEntryPointFor` 를 **하나만** 등록하면 Spring 이 그것을 모든 요청의 기본 EntryPoint 로 삼아 페이지 라우트까지 401 이 되므로, 반드시 비-API 매핑과 **쌍으로** 등록한다.

38. **인증이 필요한 백그라운드 폴러는 무동작 세션 만료를 영구히 무력화한다 — 서버는 멀쩡한데 만료가 안 온다** — Spring Session 은 **요청마다** `SPRING_SESSION.LAST_ACCESS_TIME` 을 갱신한다. 배너(`fragments/banner.html`)가 20개 템플릿 전부에서 60초마다 `/api/system/status`(인증 필요)를 치고 있었기 때문에 **탭 하나만 열려 있어도 1시간 무동작 만료에 영원히 도달하지 못했다**(2026-08-23 제보: 2시간 방치해도 로그인 유지). 진단은 접속 로그가 확정적이다 — 완전 유휴 25분 구간의 요청이 `/api/system/status` 25건뿐(60초 간격, 전부 200)이었고, 브라우저를 닫아 폴링이 끊긴 13시간 뒤 첫 요청은 정상적으로 302 → `/login` 이었다. **서버 설정을 의심하지 말 것.** 대응은 `SessionTimeout.managedInterval()` — 유휴 2분 초과·숨은 탭이면 실행을 건너뛴다. **새 배경 폴러를 추가하면 반드시 이걸 경유할 것**(`setInterval` 직접 사용 금지). ⚠ **폴링을 끄면 드러나는 2차 함정:** `LAST_ACCESS_TIME` 은 요청 **진입 시 1회**만 찍히므로 90분짜리 XHR 업로드나 35분짜리 MAT SSE 는 시작할 때 한 번만 세션을 갱신한다 — 지금까지 장시간 업로드가 멀쩡했던 건 순전히 배너 폴링 덕이었다. 그래서 진행 중 작업은 `registerActivityGuard(fn)` 로 선언해야 하고 모듈이 5분 주기로 `GET /api/session/keepalive` 를 대신 친다(등록: upload-queue `_uploading` / analyze `_aiAnalysisInProgress` / compare `_cmpAiInFlight` / ai-chat `_sending` / progress `analysisRunning` / core-dump-progress `analysisLive`). ⚠ **활동 가드에는 끝나는 작업만 넣을 것** — `account.html` 의 `memoWillWarnOnLeave`("미저장 텍스트 있음")처럼 무기한 참일 수 있는 조건을 넣으면 메모 한 글자로 세션이 불멸이 된다. 그런 화면은 세션을 연장하지 않고 **이 탭만 이동을 막는** `registerNavigationBlock(fn)` 을 쓴다(작성 중 내용이 없으면 false 를 돌려 평범하게 이동). 가드가 영구히 참이 되는 실제 경로가 있어(`progress.html` 의 SSE `onerror` 는 HEAD 가 `!ok` 면 어느 종료 분기도 안 탄다) **8시간 런어웨이 백스톱**을 둔다. ⚠ 만료 시 `location.replace` 도 `beforeunload` 를 발화시켜 사용자가 '취소'하면 자동 이동이 무산되므로(함정 36), `addEventListener` 로 등록된 beforeunload 핸들러 4곳은 첫 줄에서 `SessionTimeout.isExpiring()` 을 보고 빠진다 — **새 이탈 경고를 붙이면 이 줄도 함께 넣을 것.** ⚠ 만료 간격은 설정값이 아니라 `HttpSession.getMaxInactiveInterval()`(`SessionModelAdvice`)에서 읽는다 — `setDefaultMaxInactiveInterval()` 은 신규 세션에만 적용돼 설정값을 쓰면 기존 세션이 경고 없이 401 을 맞는다. 활동 이벤트에 **`mousemove`·`scroll` 을 넣지 말 것**(마우스 지글러·프로그램적 자동 스크롤이 세션을 되살려 이 버그를 재현한다). 회귀 방어 `SessionTimeoutTemplateSmokeTest`(5). **2026-09-26 검증:** `managedInterval` 틱은 `noteServerTouch()`(서버 접촉 시각)만 찍고 만료 판정의 `lastActivityAt` 은 사용자 입력·`touch()` 만 갱신하므로, 갱신 주기를 10초로 줄여도 만료 시점(마지막 활동 + 만료 간격)은 같다 — 서버 `LAST_ACCESS_TIME` 도 유휴 2분에서 폴링이 멈춰 함께 멈춘다. 진짜 지뢰는 `init()` 의 페이지 로드 = 활동 기록이다(함정 69).

47. **로그인 성공 훅에 코드를 더할 때는 OTP early-return 보다 앞인지 확인할 것 — 뒤에 두면 OTP 모드에서만 조용히 안 돈다 (2026-09-13)** — `AuthEventListener.onSuccess`(`InteractiveAuthenticationSuccessEvent`)는 **1차(ID/PW) 통과 시점**에 발행되는데, 함수 첫머리에 "OTP 모드면 여기서 기록하지 않는다"는 early-return 이 있다(완전 인증 성공은 `TwoFactorService` 가 기록하므로 옳다). 비밀번호 실패 카운트 리셋을 그 뒤에 두면 **OTP 모드에서 카운트가 영원히 리셋되지 않아**, 며칠에 걸친 오타가 누적돼 멀쩡한 사용자가 어느 날 갑자기 잠긴다 — 예외도 로그도 없고 2FA 를 끄면 재현되지 않는다. "비밀번호가 맞았는가"에 반응하는 로직은 early-return **앞**, "완전 인증이 끝났는가"에 반응하는 로직은 뒤. 같은 이유로 잠금 판정(`LoginAttemptService`)은 컨트롤러가 아니라 이벤트 리스너 한 곳에 두고, DB 쓰기 실패는 리스너에서 흡수한다(흘리면 "비밀번호가 틀렸다"가 500 화면이 된다 — 대신 `[LockPolicy]` 경고를 남긴다. 잠기지 않는 쪽으로 열리는 실패라 조용히 넘기면 안 된다). 운영 실측으로 OTP 모드에서 오답 2회 후 정답 로그인 시 카운트 0 리셋을 확인했다(`/login/otp/setup` 유도와 동시).

69. **자동 갱신 화면을 `location.reload()` 로 만들지 말 것 — 페이지 로드가 곧 '사용자 활동' 이라 세션이 영원히 만료되지 않는다 (2026-09-26)** — `session-timeout.js` 의 `init()` 은 페이지 로드마다 `lastActivityAt = now()` 를 쓴다(뒤로/앞으로·주소 입력이 유휴로 오판되지 않게). 그래서 타이머로 스스로 reload 하는 화면은 60분 만료에 절대 닿지 않는다 — 배너 폴링이 세션을 불멸로 만들던 함정 38 과 결과가 같고, 이번엔 서버가 아니라 **클라이언트 시계**가 되돌아간다. 대시보드·현황판의 '화면 자동 갱신 주기' 는 그래서 `live-refresh.js` 의 **부분 갱신**(조각 교체)이고, 조각이 한쪽에만 있어 따라갈 수 없을 때도 자동 reload 대신 **폴링을 멈추고 '새로고침' 버튼**을 보인다(사용자 클릭은 정당한 활동). 대시보드의 종전 '분석 완료 → reload' 도 `refreshNow()` 로 바꿨다. ⚠ 조각 루트에 페이지의 조상 `th:if` 를 빠뜨리면 파일 0건일 때 "조각은 있고 페이지엔 없음" 이 되어 폴링이 멈춘다(증상은 안내 버튼 — 루프는 아니다). 회귀 방어 `LiveRefreshSessionContractTest`(reload 는 클릭 핸들러 1곳·`touch` 금지·raw 타이머 금지·`managedInterval` 틱이 `lastActivityAt` 을 안 만짐)·`DashboardDetectSummaryTest.fragmentsShareMarkupAndFollowPageConditions`.

70. **DB 장애는 `@ControllerAdvice` 로 못 잡는다 — 세션 필터에서 죽어 `/error` 로 가고, 그 오류 페이지가 세션·CSRF·배너를 건드리면 다시 죽는다 (2026-09-26)** — Spring Session JDBC 라 쿠키 있는 요청은 인가 필터의 세션 조회(`findById`)에서 예외가 나며, 이건 `DispatcherServlet` 밖이라 `GlobalExceptionHandler` 는 무관하다. Tomcat 의 ERROR 디스패치는 세션 필터를 타지 않아 익명이고, 종전엔 `/error` 가 permitAll 이 아니라 **페이지는 `/login` 302, `/api/**` 는 401 SESSION_EXPIRED** 로 바뀌어 화면이 "세션이 만료됐다" 고 했다(로그인 폼은 "아이디 또는 비밀번호 오류"). 대응은 `DbAwareErrorController`(예외 사슬 판정 → 503) + `SecurityConfig` 의 ERROR 디스패치 허용·CSRF 면제 + **자립형** `error/db-unavailable.html`. ⚠ 오류 템플릿에 `th:replace` 배너·`${_csrf}`·`#session` 을 넣지 말 것(렌더 중 세션 저장소 접근 = 두 번째 예외 → Whitelabel 로 후퇴). ⚠ API/HTML 분기는 Accept 가 아니라 **원래 경로(`/api/`)·`X-Requested-With`** 로 — fetch 의 기본 Accept 는 HTML 매핑을 고른다(함정 14). ⚠ 판정은 `DbHealthService` 캐시가 아니라 **예외**로(예외가 진실). ⚠ `java.net` 소켓 예외만으로 DB 장애로 보지 말 것 — LLM·SSH 타임아웃이 503 DB 안내로 둔갑한다(`DbOutageDetector` 는 DB 계층 예외와 AND). 회귀 방어 `DbOutageDetectorTest`·`DbAwareErrorControllerTest`·`DbOutageDisplaySmokeTest`.
