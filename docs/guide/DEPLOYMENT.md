## 패키지

**Kubernetes 배포 패키지 (`/opt/genspark/heapApp_k8s`, 2026-09-05 재작성 — Chroma 포함, RHEL 8.10/9.6 · 2026-09-14 2.5.1 리패키징 verify 39/39 · 2026-09-22 매니페스트 2.5.7 + 개발망 오버레이 `dev-k8sdata`):** ⚠ **노드에 직접 반입한 이미지는 이름이 `localhost/heap-analyzer:<ver>` 다**(`podman save` 가 붙인다) — 오버레이 `images.newName` 을 그대로 `heap-analyzer` 로 두면 kubelet 이 `docker.io/library/heap-analyzer` 를 찾아 ErrImagePull. ⚠ **프로비저너 없는 클러스터의 로컬 디스크는 `k8s/storage/setup-local-storage.sh <오버레이> check|apply|generate`** 가 정적 local PV(claimRef 로 PVC 이름 고정·Retain·nodeAffinity)·StorageClass·패치를 `<오버레이>/storage/*.yaml` 로 생성하고, **local PV 는 용량을 강제하지 않으므로 XFS 프로젝트 쿼터로 볼륨별 한도를 건다**(쿼터 없으면 힙덤프가 디스크를 채울 때 MariaDB 도 멈춤). 조건은 `<오버레이>/storage.env` 한 곳, 배포 후 재실행 시 매니페스트 용량은 **배포된 PVC 값을 따르고 쿼터만** 바뀐다(PVC·STS 용량 불변). 운영망 이행 절차는 k8s 트리 `docs/DEV-K8SDATA.md` §6.  ⚠ 앱에 설정 키를 추가하면 `config/application.properties` 에도 넣고 `sync-config.sh` 로 ConfigMap 을 재생성할 것 — 빠지면 기동은 되지만 치환 전용 동기화라 설정 화면 변경이 파일에 반영되지 않는다(2.5.1 때 4개 누락 발견). 앱 리포와 `/opt/chroma` 를 **읽기만** 하는 별도 트리. 통합 이미지 **1개**(`heap-analyzer:<pom version>` — 앱+MAT+gdb+python venv+e5 모델+색인기)를 Pod 안에서 컨테이너 3개(`app` / `chroma` :8000 / `embed` :8001, 같은 이미지·다른 command)로 띄운다. ⚠ **이미지를 나누지 말 것** — 색인기 `sources.py` 가 앱 JAR 을 `java -cp` 로 직접 실행해 코드 상수 지식을 뽑으므로 Python·Java·JAR 이 한 파일시스템에 있어야 하고, 그래야 "색인 실행" 버튼(`RagIndexRunner`→`/opt/chroma/app/run-index.sh`)이 Java 변경 없이 동작한다(이미지의 `/app/target/heap-analyzer-<ver>.jar` 심볼릭 링크가 glob 계약을 맞춘다). 사이드카는 **127.0.0.1 바인딩**이라 Service·인증·NetworkPolicy 가 필요 없고 앱 설정이 호스트와 동일한데, 그 대가로 **프로브는 `exec curl` 이어야 한다**(kubelet 의 httpGet 은 Pod IP 로 접속해 loopback 에 닿지 않는다). 색인기 임베딩은 `EMBED_REMOTE_URL`(app 컨테이너 env 만)로 사이드카에 위임 — `embedder.py` 원격 모드(기본 OFF, 호스트 무영향)이며 `embed_server.py`/`chroma-entrypoint.sh` 가 그 변수를 지워 **자기위임 루프**를 막는다. 컨테이너판 `run-index.sh` 는 JAR 복호화 대신 `SPRING_DATASOURCE_*` env 에서 `HEAPDB_*` 를 유도한다. ⚠ `requirements.lock` 은 python3.9 기준이라 이미지(jammy 3.10)에서 `typer 0.23.2` 의 조건부 의존 `click>=8.2.1` 한 줄만 완화한다(`build-image.sh`). ⚠ `embed` limit 은 900Mi 미만 금지(기동 피크 cgroup 656MB), Chroma 는 단일 writer 라 `replicas 1`+`Recreate` 필수. 검증은 `scripts/verify-image.sh` 가 **podman pod**(k8s Pod 처럼 netns 공유)에 MariaDB+chroma+embed+app 을 띄워 색인→벡터 검색→`/api/settings/rag/chroma/status` 까지 확인한다(운영 DB 미사용, 호스트 Chroma 스택은 메모리 때문에 `stop_chroma_all.sh` 로 잠깐 내릴 것). RHEL 8/9 차이(podman 4.9/5.x·cgroup v1/v2·SELinux·CRI-O/containerd 반입 명령)는 `docs/COMPATIBILITY.md`.

**폐쇄망 k8s 설치 패키지 (`/opt/genspark/k8s_install`, 2026-09-05 · 2026-09-06 단일 진입점화):** 사용자가 실행하는 스크립트는 **딱 둘** — 타깃은 `k8s_install.sh`(**시작 시 설치 방식 k3s/kubeadm 을 먼저 묻고** → 번호 메뉴 1점검/2설치/3삭제/4cgroup전환/m방식변경 + y/N, 기본 N. 선택한 방식은 헤더에 상시 표시되고 삭제만 방식 무관), 빌드 머신은 `build-bundle.sh`. 나머지는 `lib/` 내부 모듈이라 직접 실행하지 않는다(`scripts/` 에서 이름을 바꾼 이유). 점검·설치는 `lib/rpm-status.sh` 가 **RPM 설치 상태표**(INSTALLED/DIFFERENT VERSION/NOT INSTALLED/MISSING × 번들/OS/OS저장소)와 **"이번에 설치되는 RPM"** 목록을 보여준다 — 참고 스크립트 `/root/xrdp-offline/offline_xrdp_install.sh` 의 관례다. ⚠ 대화형 입력은 `</dev/tty` 로 고정하지 말 것(파이프 실행이 죽어 자동 점검 불가) — `ask()` 가 tty 없으면 stdin 으로 떨어진다. ⚠ 한글 라벨은 `printf %-Ns` 가 **바이트**로 패딩해 어긋난다 — `wc -L` 로 표시 폭을 재는 `row()` 를 쓸 것. 인터넷 없는 사내망 RHEL 8.10(32GB)에 k8s 를 설치하는 오프라인 번들(928MB) + 스크립트 10종. ⚠ **버전을 함부로 올리지 말 것** — k8s **1.35 는 cgroup v1 기본 비활성화, 1.36 은 완전 제거**라 cgroup v1 노드에서 kubelet 이 **아예 기동하지 않는데 RHEL/Rocky 8 은 cgroup v1 이 기본**이다(9 부터 v2). k3s stable 은 이미 v1.36.4 라서 최신을 받으면 그대로 실패한다 — 그래서 k3s `v1.34.11+k3s1`/kubeadm `1.34.11` 로 고정했고 판정은 `env.sh` 의 `CGROUP_V1_MAX_MINOR` 한 곳(`cgroup_version_compatible()`)에 있다. k3s 가 권장 경로(containerd 내장 → 런타임 스큐 없음, 산출물 4개); kubeadm 은 `pkgs.k8s.io` 의 **cri-o stable 이 v1.32 까지만** 공개돼 있어 CRI-O 대신 containerd 정적 배포본을 쓴다. ⚠ RPM 은 `--resolve` 만 쓰고 **`--alldeps` 금지** — glibc·systemd 까지 170개를 끌어와 타깃 base OS 를 의도치 않게 업그레이드시킨다. ⚠ dnf 4 는 `--repo` 와 `--disablerepo` 동시 사용을 거부하고, `--repofrompath` 는 repodata 를 요구하므로 **RPM 파일 직접 설치**를 쓴다. ⚠ dnf 출력 파싱은 **`LC_ALL=C` 필수**(한국어 로케일에서 통과를 실패로 오판). 최종 안전망은 타깃에서 root 로 돌리는 `verify-bundle.sh` 의 **의존성 모의 설치**(`--setopt=tsflags=test`) — 번들이 빌드 머신 기준이라 타깃에 빠진 패키지를 설치 전에 이름까지 찍어 준다. ⚠ **빌드 머신이 Rocky, 타깃이 RHEL 이면 base OS 패키지를 번들에 넣지 말 것** — vendor 가 `Rocky` 라 RHEL 패키지를 교체하게 된다(초기 번들에 실제로 8개가 있었고 `/root/xrdp-offline/offline_xrdp_install.sh` 가 같은 상황을 차단한다). k8s RPM 5개는 vendor 가 `obs://…isv:kubernetes` 라 중립이고, base 의존성은 `env.sh` 의 `BASE_DEPS_*` 로 선언해 **타깃 RHEL 미디어**에서 조달한다(preflight 가 installed/available/missing 3-state 판정, SELinux 꺼져 있으면 container-selinux 는 SKIP). ⚠ 미등록 RHEL 에서는 **`--disableplugin=subscription-manager`** 없이는 dnf 가 매번 구독 오류를 낸다(`DNF_OFFLINE_OPTS`). 2026-09-05 aibank01d(RHEL 8.10)에서 `verify-bundle.sh` 20/20·`preflight.sh` 15/1(디스크 기준값) 실측 — **Rocky 번들이 RHEL 에서 OS 패키지를 건드리지 않고 의존성이 풀림**을 확인했다. **2026-09-16 사내망(ldkrap1d, RHEL 8.10) 첫 실설치**에서 두 가지가 드러났다. ⚠ **containerd 는 반드시 `containerd-static-*` 배포본**(`env.sh` 의 `CONTAINERD_TARBALL`) — 이름에 `static-` 이 없는 공식 tar.gz 는 glibc 2.34 빌드라 RHEL 8(2.28)에서 `GLIBC_2.32 not found` 로 **실행 자체가 안 된다**. 진짜 문제는 **tar.gz·raw 바이너리가 모든 검사의 사각지대**였다는 것이다 — SHA256 은 파일이 온전한지만 보고 dnf 모의 설치는 RPM 만 보므로, 점검이 전부 PASS 인데 설치 도중(swap·fstab·커널모듈·`/usr/local` 을 이미 바꾼 뒤) 터졌다. 그래서 4겹으로 막는다: 수집 시 정적 링크 가드(`fetch-kubeadm.sh`) · 점검 [2/4] **런타임 바이너리 호환성**(호스트 glibc 대조 + `--version` 실제 실행, `common.sh` 의 `glibc_compatible`/`bin_probe`/`check_bundle_binary`) · 설치 **직전** `assert_bundle_binary`(시스템 변경 전 중단) · 두 배포본 공존 시 `CONTAINERD_TARBALL` 우선 선택(glob 은 동적본을 먼저 잡는다). ⚠ **objdump/readelf 를 쓰지 말 것** — minimal RHEL 에 binutils 가 없다. `.dynstr` 문자열을 `grep -ao 'GLIBC_[0-9.]*'` 로 읽는다. ⚠ **swap 은 절대 묻지 않고 끄지 말 것**(2026-09-16 사용자 지적) — 종전 `install-kubeadm.sh` 는 swap 이 켜져 있으면 말없이 `swapoff -a` + `/etc/fstab` 주석 처리를 했다. swap 은 DB·WAS 가 함께 도는 호스트의 전역 설정이다. 지금은 kubeadm 경로에서만, 설치 직전에 **3지선다**(끄고 영구 반영 / 이번 부팅만 / 취소)로 묻고 `SWAP_POLICY`(`env.sh`: `ask|permanent|session|abort`)로 자식에게 넘긴다. **기본값은 취소**이고, `lib/install-kubeadm.sh` 를 직접·비대화형으로 실행하면 정책이 없으므로 **끄지 않고 중단**한다(조용히 꺼지는 쪽으로 열리면 안 된다). k3s 는 원래 swap 을 켠 채 기동하므로(`--kubelet-arg=fail-swap-on=false`) 묻지 않는다 — **swap 을 끌 수 없는 서버의 답은 k3s 다.** ⚠ kubeadm 에 같은 우회(`--fail-swap-on=false`)를 넣지 않은 이유: kubelet 1.34 바이너리에 `swap configuration is not supported with cgroup v1` 문자열이 있어 **RHEL 8(cgroup v1)+swap 은 미검증 영역**이다. ⚠ 다른 하나는 **반입 중 `lib/rpm-status.sh` 한 개 누락** — source 실패 메시지가 main 의 `clear` 에 지워지고 `set -e` 도 없어 `rpmstat_report: command not found` 와 **엉뚱한 안내("RHEL 미디어 등록 필요")** 만 남았다. 지금은 `k8s_install.sh` 가 모듈의 존재·문법·함수 정의를 확인하고 clear 이전에 중단한다. 실제 클러스터 기동은 여전히 미검증.
